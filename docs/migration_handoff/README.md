# 開発・常駐Macへの移行

この文書は、別のMacや開発エージェントが続きを進めるための引き継ぎメモです。リポジトリを取得しても、稼働中の端末の同期設定は変わりません。

## 目指す状態

常時起動しているMacが、同じCodex／Claudeアカウントの残量を15分ごとに取得し、iCloud Driveへ保存します。普段使うMacとiPhoneはそのデータを表示します。取得にはAIモデルへの会話・生成リクエストを使いません。

元の依頼は、CodexとClaudeの5時間枠・週間枠、Codexのクレジットをまとめたウィジェットを、MacとiPhoneの両方で使えるようにすることです。提供されない枠や未接続のサービスは、数値を作らず「—」などで区別してください。

## 現在の状態

| 対象 | 状態 |
| --- | --- |
| Codexの取得 | 公式CLIのapp-server経由で実値取得を確認済み |
| Claudeの取得 | 未ログイン表示を確認済み。ログイン後のPTY解析は未検証 |
| Macアプリ | 実値表示、iCloudへの保存、15分同期を確認済み |
| Macウィジェット | WidgetKit拡張の登録を確認済み。デスクトップ配置は未確認 |
| iPhone専用アプリ | 実機用ビルドとシミュレータ起動を確認済み。実機導入・iCloud同期は未確認 |
| iPhoneの方式 | 専用アプリかScriptableか、利用者の選択待ち。Scriptable版は未実装 |

このアカウントで確認したCodexの応答は、primaryの期間が10080分、secondaryがnullでした。primaryを5時間枠だと決めつけず、期間を使って週間枠へ割り当てる実装を維持してください。

## 先に確認すること

- 移行先MacのmacOS、Python、Codex CLI、Claude Codeの有無とログイン状態。
- 移行元と同じ対象アカウントの残量を取得できること。
- 移行先がログイン中で、スリープせずに動き、同じiCloud Driveを使えること。
- iPhoneの表示方式。回答前にScriptableをインストールしたり、選択が済んだ扱いにしたりしないでください。

新しいツールの導入やログインが必要な場合は、その端末の利用者に確認してください。認証情報は各端末で正規に設定し、リポジトリやチャットを経由して複製しないでください。

## 変更が必要な部分

`Shared/UsageStore.swift` のmacOS用 `refresh()` は、現在は端末内のApp Groupキャッシュを返します。取得処理を別のMacへ移すときは、普段使うMacでもiCloudの同期ファイルを読み、その結果を表示できるように変更してください。

現在の取得・保存は `tools/sync_usage.py`、Macアプリからの実行とLaunchAgentの設定は `Mac/MacSync.swift` にあります。ウィジェットの更新は `Widget/AIUsageWidget.swift`、共通の表示は `Shared/UsageCard.swift` です。UIとは独立して、取得スクリプトの手動実行から確認できます。

## 切り替える順番

1. 移行先Macで、`--output` を使って本番の `usage.json` とは別の確認用ファイルへ出力します。CodexとClaudeの接続状態、枠の期間、取得時刻を確認します。
2. 移行先Macの自動実行でも確認用ファイルが更新されることと、iCloud経由で他端末へ届くことを確認します。
3. 普段使うMacのiCloud読取りと、選択されたiPhone方式を実装・確認します。
4. 利用者と切り替え先を確認し、移行元の取得ジョブを停止してから、移行先を共有用の `usage.json` へ切り替えます。同じファイルに2台で同時に書き込まないようにします。
5. 移行先で更新した取得時刻が、共有ファイルと表示側の両方へ反映されることを確認します。

移行先で更新できない場合は、確認用ファイルでの作業を止め、移行元の同期を継続します。切り替え後に戻す場合は、移行先の取得を止めてから元のジョブを再開してください。秘密情報の転送やMacのセキュリティ設定の一括変更は、復旧手段にしないでください。

## 引き継ぎの完了条件

常駐Macでの取得・iCloud同期、普段のMacとiPhoneでの表示がつながっていることを確認してください。取得スクリプトや片方の端末のビルド成功だけでは、移行全体の完了とはしません。

ClaudeやiPhoneの実機確認が未完了の場合は、その範囲と、利用者に必要な操作を明示してください。取得失敗時の前回値・取得時刻の保持と、リセット時刻を過ぎた枠の残量を「—」、リセットまでの時間を「更新待ち」にする挙動を維持してください。
